## Findings and remaining limits

1. The ownership comment overstates exclusivity at `P:43` and `P:69`. Any launcher that independently uses the exact doubled-slash string will still lose it on child exec. This is a naming convention, not authenticated provenance. The checked bgl-launch uses the distinct normal spelling, so this does not block the requested test. Reserve the new spelling for 2130 and describe the guarantee that narrowly.

2. Ownership remains an exact whole-variable check at `P:78`. A child inheriting two separate entries is handled correctly. A child inheriting one colon list containing both spellings, or v4's path followed by `:/x.dylib`, retains the whole variable and can load the inject. I reproduced this in `composition-check.log`. This limitation already exists in v3's matching design and does not affect the exact variables 2130 emits. It prevents claiming containment of edited or recomposed environments. Preserve the narrow test scope. Token-aware removal would be a separate change if that broader guarantee is required.

3. An insert or dependency failure can still kill Freeform before its constructor or watchdog runs. The concrete path is `D/DyldRuntimeState.cpp:667`, which reports an insert failure when policy disallows it, followed by the halt at `D/dyldMain.cpp:703`. Dependency failures occur in the following load phase. The doubled slash does not add a fallback to stock or isolate GPU side effects. This remains acceptable only for the requested isolated test.

I found no new path-prefix restriction in the connected AMFI stand-in. `K/bsd/kern/sweet_amfi.c:266` checks the signature against a vnode and mount, and `:592` grants dyld policy bits by process architecture. Its Sandbox stand-in at `:282` describes permissive checks, rather than an insert-path allowlist. `D/Loader.cpp:1636` performs library validation through a file descriptor, and `K/bsd/kern/kern_descrip.c:4415` forwards the file object to MAC validation. The extra slash does not change those objects or the Mach-O signature bytes. This does not certify Apple's production AMFI or an uninspected external policy that compares a full raw path.
